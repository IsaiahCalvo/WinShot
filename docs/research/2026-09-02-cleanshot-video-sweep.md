## 3. PixelSnap 2 measurement — implementation spec for WinShot

WinShot already owns four of the five hard parts: a frozen per-monitor snapshot, DPI-correct 1:1 overlay surfaces, a nearest-neighbour pixel loupe that is **already better than PowerToys'** (their magnifier issue #20850 is still open), and dirty-region invalidation. What is missing is ~200 lines of arithmetic and a rendering vocabulary.

### 3.1 Interaction model

Hover measures. No mode inside the mode, no handle to grab, no click.

| Gesture | Result |
|---|---|
| Move the mouse | Four rays cast from the cursor pixel; horizontal and vertical spans draw, pill reads `W × H`. Continuous, no click. `cB-2U-3B3dw@00:11-00:16` |
| `H` | Hold horizontal distance — freeze this span as a persistent crimson dimension with its pill; keep measuring. |
| `V` | Hold vertical distance — same, vertical. |
| `Shift+H` / `Shift+V` | Drop a persistent **blue** screen-wide guide at the cursor, snapped to a real element edge. A parallel pair auto-labels its own gap. `cB-2U-3B3dw@00:27-00:34` |
| Mouse wheel | Adjust tolerance live, ±15, clamped 0–255, value shown in the HUD. |
| Click the object | Copy dimensions to the clipboard, toast `Dimensions copied`. `cB-2U-3B3dw@00:73` |
| Click the pill | Capture just that object (reuses the existing `SelectedByPaneClick` path). `cB-2U-3B3dw@00:53-00:58` |
| `Backspace` | Remove the most recent hold. |
| `Esc` | First press clears holds and guides; second press exits. |
| Right-click | Small dark menu listing all of the above with shortcuts — **Measure mode only**; right-click-cancels stays in Area/Window, that reflex is already trained. |

Colour is the grammar and it must not blur: **crimson = a distance the app computed** (T-serif end caps, midpoint pill); **blue = a guide you placed** (edge-to-edge, no caps, no pill unless paired).

### 3.2 Entry points

- `SelectorMode.Measure` on `FastRegionSelectorDialog` — no new window class; reuses `Rent()`/`Return()` pooling, the frozen snapshot, the per-monitor panes and the 8 ms follow timer verbatim.
- `"measure"` added to `CommandServer.ValidCommands` (currently 19 strings).
- `Settings.HotkeyMeasure` (default `Ctrl+Shift+9`) plus one `Reg(...)` in `RegisterHotkeysCore`.
- Tray item beside "All-in-One…".
- `AllInOneAction.Measure` plus a `BarButton` in `FastAllInOneSelectorDialog`.

### 3.3 Snapping algorithm

Three tiers. Tier 1 alone already reads as PixelSnap.

**Tier 1 — 4-ray colour-delta walk.** New `src/WinShot/Capture/EdgeSnap.cs`, a direct port of PowerToys `MeasureToolCore/EdgeDetection.cpp` (MIT — keep the notice). ~60 lines. Six details that must **all** be copied or it feels wrong:

1. Compare each stepped pixel against the **fixed cursor pixel**, never the neighbour. That makes it a contiguous-run walk, not a gradient detector.
2. Return the **last similar** coordinate, so `Width = right - left + 1`. Get this wrong and every measurement is off by one — the classic bug in this feature.
3. Clamp the cursor to `[1, dim-2]` so the walk cannot read out of bounds.
4. Rays clamp to the frame edge and degrade to full-monitor rather than fail.
5. The four rays are **independent** — left/right walk the cursor's scanline, top/bottom its column. That is why hovering a gap measures the gap for free. Sell it in the UI.
6. Skip `CURSOR_OFFSET_AMOUNT_X/Y = 4`. It exists only for continuous capture; WinShot freezes, so drop the fudge factor.

Metric: summed L1 over B,G,R,A masked to `0xFF` (PowerToys' default), with strict per-channel as a toggle. Do **not** write SIMD in C# — four bytes, the memory access dominates. Operate on `_frozen` locked once per session via `LockBits` into a cached `BitmapData`, **stride-indexed** — never `Bitmap.GetPixel`, never `Width*4` for stride (`RowPitch != width` is the same trap as `SKPixmap.RowBytes`).

**Tier 2 — structural snap. Already shipped.** `WindowEnumerator.GetSnapRectangles()` (EnumWindows + child windows + client rects, deepest-first, timeout-bounded) and `MsaaElementDetector.ElementRectFromPoint` give real window / control / DOM rects. Feed the pixel result into the existing `BuildLadder` as one more rung so the wheel walks pixel- and HWND-detected candidates in one merged list. **That blend is the thing neither PowerToys nor PixelSnap has** — colour-delta fails on Win11 mica chrome exactly where the HWND rect is exact, and vice versa on photos and canvases.

**Tier 3 — object bounding box.** Scanline flood fill from the cursor pixel using the same `PixelsClose` predicate, capped ~250k pixels, falling back to the 4-ray cross. Gives the two-stage tighten PixelSnap shows on photo cards (`302×236` padded card → `286×215` true photo bounds, `cB-2U-3B3dw@00:25-00:26`). Gate behind a modifier, or trigger only when the cross returns implausibly small.

### 3.4 Tolerance

`byte _tolerance = 30` (PowerToys' tuned default for summed-L1). Wheel step 15, clamp 0–255, current value rendered in the HUD so the change is legible. Persist as `Settings.MeasureTolerance` with a Low/Medium/High (15/30/60) control in the Screenshots pane. **Do not ship the engine without the knob** — every gradient, acrylic surface, drop shadow and anti-aliased glyph will otherwise read as "the snapping is broken". PixelSnap gives tolerance an entire preferences tab and a Touch Bar segment (`cB-2U-3B3dw@00:35-00:46`); that is not decoration.

Note: in Measure mode the wheel is rebound from the hover ladder to tolerance. The ladder gesture stays in Area/Window mode.

### 3.5 HUD rendering

Add `ThemePalette.Measure = #E0244A`. Add `SelectorChrome.DrawDimension(g, clientSize, Point a, Point b, string label)`:

- Aliased 1 px pen in crimson, no dashes, no glow. `PaintSurface` already opens with `SmoothingMode.None`, so crisp hairlines are free.
- `FEET_HALF_LENGTH = 2` T-serifs at both ends. Copy PowerToys' endpoint-exclusive dance: extend the line 1 px past, then pull the serif back 1 px. This off-by-one is what separates a polished ruler from a sloppy one.
- Pill centred on the **segment's own midpoint** — you read the number where the gap is. Reuse the existing `MeasureLabel` + `DrawLabel`, adding a `fullyRounded` flag (radius = height/2) used only by measurement pills so the existing radius-6 selection readout does not move.
- Bare integers, no `px` suffix, for single-axis holds. `W × H` (U+00D7 — `PaintSurface` already uses it) for the cross.
- Second line with the DIP value whenever the pane's monitor DPI ≠ 96: `296 × 118` over `197 × 79 dip`. Port `MeasurementLogic.h`: `Dip = px * 96 / monitorDpi`. **This matters more on Windows than macOS** — Isaiah's primary runs 150 %, so "24 px" is really "16 dip". Take DPI from the pane's own monitor, never the process.
- All arithmetic in device pixels of the frozen bitmap; convert only at the label.
- **No tween.** `RectangleTween` is right for the Area-mode selection glide and wrong here — spinning digits for 200 ms reads as a glitch. Skip `Retarget` in Measure mode.

Sticky canvas: `List<Measurement>` where `record Measurement(Rectangle Bounds, bool Horizontal, bool Vertical, string Label)`, drawn before the live one, each invalidated through the existing `InvalidateScreenRect` so the dirty-region discipline survives at 4K.

Guides: `List<int> _guidesX, _guidesY`, pushed through the existing `SnapCoordinate` against `_snapEdgesX`/`_snapEdgesY` so they snap to real element edges for nothing. Hit-test within 4 px to drag, swapping to `Cursors.SizeWE`/`SizeNS` via the existing `CursorForCurrent`.

## 6. Refuted / dropped — do not re-propose

Each failed skeptic review against the actual WinShot source. One line of why.

**Capture selector**
- *Overlay tears down after every shot* — repeat-capture already exists twice: `capture-previous` replays `LastCaptureRegion`, and `TryRestoreLastRegion` reopens All-In-One on the same framed rect.
- *Selection should be corner brackets, not a solid outline* — the CleanShot claim contradicts the same audit's handles-on-a-1px-border description; pure restyle on contradictory evidence.
- *No dim/scrim ramp on overlay entry* — instant dim is a deliberate open-latency optimization (surface creation was measured at 200–900 ms); a 120 ms fade risks exactly what the parking design exists to avoid.

**Quick-actions overlay**
- *No Quick Look / full-size preview* — already exists as Pin: card button, bare `P` in `OnOverlayKeyDown`, "Pin to the screen (P)" menu row → `FastPinWindow`, a full frameless topmost image window.
- *Context-menu hover should be accent, not grey* — Win11 context menus use exactly this subtle grey; the accent is reserved for keyboard focus, where it carries meaning.
- *"Move to Recycle Bin" should sit above "Show in folder"* — Windows convention is destructive-last; moving it up puts a destructive item under the cursor path to a harmless one.

**History**
- *Backspace-on-hover delete is missing* — mac idiom; `Key.Delete` already deletes the selection with no confirm dialog and reselects the neighbour.
- *Hover should be a border + one Restore pill, not five buttons* — every verb works and is discoverable; swapping five labelled buttons for one pill trades discoverability for a mac look.
- *Quick preview should be anchored with a caret* — Windows has no anchored-preview convention; centred near-native is correct here.
- *No search field* — filenames are pure timestamps, so there is no corpus to match until the source-app metadata gap lands. The five chips + Date/Name/Size sort cover real filtering.

**Recording**
- *Start stalls up to 2 s behind a duplication release* — `ReleaseResources` is `Monitor.TryEnter(Gate, timeoutMs)`: a lock-acquisition ceiling under contention, not a wait. Common path is instant, and moving the release earlier reopens the documented `E_INVALIDARG` race.

**Scrolling / pin**
- *Live stitch preview shrinks instead of filling* — deliberate and commented: the shrinking overview is what tells the user whether the capture is keeping up.
- *A pinned screenshot can't be dragged out* — true, but the proposed fix is a bottom-centre "Drag me" grabber, which Isaiah has already rejected. Drag-out exists on the card and in the editor.
- *Editor eyedropper can't sample live screen pixels* — by design; the real need is covered by the system-wide colour picker gap, not counted twice.

**PixelSnap measurement**
- *Measurement would inherit the 200 ms `RectangleTween` glide* — nothing to animate yet; folded into the engine gap as a one-branch "never Retarget in Measure mode" note.
- *Measurements can't be baked into a capture* — `CropFrozen` + `CaptureExclusion` already give the correct plumbing; folded into the sticky-canvas item.
- *Crosshair is guide-white and hidden behind Ctrl* — visibility is already a shipped three-way user setting; the crimson-in-measure-mode note belongs to the dimension-vocabulary item.
- *No anti-aliasing hysteresis or edge-confidence feedback* — speculative pre-tuning of code that does not exist. Add only if the shipped tolerance knob proves insufficient.

**Settings / brand**
- *Bound shortcuts need physical key wells and zebra striping* — the `HotkeyBox` template already distinguishes bound (normal foreground) from unbound (`TextDisabledBrush` "Record shortcut" placeholder); zebra on 8 rows solves a problem the list does not have.
- *No contextual Quick Tips* — same widget and same settings flag as first-run onboarding; keeping it separate double-counts and invites a tip framework nobody asked for.

## Appendix — sequencing

Do Phase 1 as one sweep. It is ~47 items, nearly all effort S, mostly one-line defaults, one-method chrome additions, and reuse of motion helpers the codebase already owns — and it is where the "CleanShot feel" actually lives. Nothing in Phase 1 needs a new subsystem.

Phase 2 splits cleanly into four independent tracks that do not block each other: **selector** (mouse-up confirm, Space-to-window, handles, timer, ratios), **card + editor loop** (round-trip, shortcuts, copy/paste, toolbar rebuild), **settings truth** (after-capture matrix, sounds, restore-defaults, bindable commands, brand), and **measurement M1–M3**.

Phase 3 has exactly one hard prerequisite: **the recording events sidecar.** Studio Mode, zoom timeline, cursor customization and video backgrounds all sit behind it, and the sidecar itself is cheap because both low-level hooks already exist. Decide the render pipeline (Composition frame pipeline vs FFMpegCore's `IPipeSource`) *before* writing any of it — that decision, not the UI, is the actual project.
